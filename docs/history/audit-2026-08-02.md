## 2. Critical Bugs

### BUG A — `T27 → I32` — Silent Integer Overflow
✅ FIXED. `ir/types.rs:126` now `ManiType::T27 => IRType::I64`.

### BUG B — `for` keyword resolves to `"sync"` in path segments
✅ FIXED. The `For => "sync"` arm is gone from `parser/mod.rs`.

### BUG C — CSE type hardcoded to `I64`
⚠️ PARTIAL. The explicit `ty: IRType::I64` comment in the CSE block is gone, but
`optimize.rs:449` still has a catch-all `_ => IRType::I64` in the type-inference helper.
This means any IR type not explicitly mapped falls back to I64. Needs review to ensure
CSE-created temporaries inherit the correct type from the original instruction.

### BUG D — `Tresult` keyword is lexed but never parsed
❌ NOT YET. `lexer.rs:167` still produces `TokenKind::Tresult` for the keyword `tresult`
and no parser rule matches it. See §10b for full implementation plan.

### BUG E — For-loop tuple destructuring silently drops all but first variable
⚠️ PARTIAL. `parser/exprs.rs:722` now has a comment "Support tuple destructuring" but
`names.into_iter().next()` still silently discards all but the first name. No hard error
is emitted. A user writing `for (a, b) in pairs { }` still gets wrong results silently.

**Fix needed:** Emit `CompileError` when `names.len() > 1` — "tuple destructuring in for
loops not yet supported, use a single loop variable".

## 3. Language Completeness Gaps

### Compound Assignment Operators
⚠️ PARTIAL. Added: `%=` (`PercentEq`), `|=` (`PipeEq`), `^=` (`CaretEq`) — both lexer and
parser handle these now.

Still missing: **`&=`**, **`<<=`**, **`>>=`** — no `AmpEq`, `ShlEq`, `ShrEq` tokens in lexer.

### Lambda Capture
❌ NOT YET. Lambdas are still lowered to `__lambda_N` global functions with no closure
environment. A lambda referencing an outer variable compiles but produces wrong output at
runtime. A closure environment struct (upvalue slots) is the correct fix.

### `Trint` Is Not Arbitrary-Precision
❌ NOT YET (design decision pending). `Trint => IRType::I64`. See §10d for options.
Recommendation: rename `Trint` → `T54` now; track true big-int as future work.

### `tcon` / `tany` Operators
❌ NOT YET. Neither `tcon` nor `tany` appear anywhere in the lexer, parser, or semantic
analyzer. Both are specified in DESIGN.md §5 and have T3ISA opcodes (TCON, TANY).
Need to add as binary operators throughout the full pipeline.

## 4. Architecture & Design Issues

### 4a. Global `#![allow(dead_code, unused_variables, unused_imports, unused_mut)]`
❌ NOT YET. Still present in `src/main.rs:1` and `src/lib.rs:1`. Blanket suppression
hides real dead code. Remove after cleaning up unused symbols.

### 4b. `register_builtins()` is a 150-line `insert` bomb
❌ NOT YET. Still a sequence of `self.functions.insert(...)` calls in
`semantic/analyzer/mod.rs`. Should be a `const BUILTINS: &[(...)]` table iterated in a loop.

### 4c. No Error Recovery — First Error Stops Everything
❌ NOT YET. Lexer and parser still abort on the first error. A `DiagnosticBag` pattern
(accumulate errors, continue parsing with error nodes) has not been implemented.

### 4d. `Span` Lacks End Position
❌ NOT YET. `ast.rs:6` still has `pub struct Span { pub line: usize, pub col: usize }`.
No `end_line` / `end_col`. Error messages show a single `^` caret instead of multi-char
underlines. Adding end position requires propagation through all 44 source files — large
but high-value for developer UX.

### 4e. `collect_declarations` is Order-Dependent for Traits
❌ NOT YET. Single-pass: if `impl Trait for Type` appears before `trait Trait` in source,
the trait is not yet in `trait_defs` and validation is silently skipped.
Fix: two-pass — collect all `TraitDef` first, then process `ImplBlock`s.

### 4f. Duplicate Function Names Silently Overwrite
✅ FIXED. `semantic/analyzer/mod.rs:715-717` now returns a `CompileError` for duplicate
user-defined function definitions. Builtins may still be shadowed (intentional).

### 4g. `is_struct_lit` Lookahead Is Fragile
❌ NOT YET. Still 1-2 token lookahead. `Foo { }` (empty struct literal) is still treated
as a block. Qualified-path struct literals also fail.

### 4h. `pending_gt` Is a Parser Hack
❌ NOT YET. The boolean flag for splitting `>>` into two `>` tokens is still in place.
A token-splitter step or generic-nesting depth counter would be cleaner.

### 4i. `SymbolTable::pop_scope` Silent on Underflow
❌ NOT YET. `scope.rs:37-41` does `if self.scopes.len() > 1 { self.scopes.pop(); }`.
Should `debug_assert!(self.scopes.len() > 1, "scope underflow — unmatched push/pop")` in
debug builds to catch compiler bugs early.

### 4j. Module System Half-Implemented
❌ NOT YET. `use std::io` still only validates the module name; all stdlib functions are
pre-registered as builtins regardless. `load_user_module` still skips `impl` blocks,
re-exports, and `pub` filtering. Circular import guard's `canonicalize` fallback can still
cause duplicate loading.

## 5. Type System Issues

### 5a. `ManiType::Unknown` Propagates Silently
⚠️ PARTIAL. `WarningCollector` and `WarningKind` infrastructure now exist (`error.rs`),
with variants for UnusedVariable, UnusedFunction, Shadowing, UnreachableCode,
IntegerOverflow, DivisionByZero. However there is **no `UnknownType` variant** and no
warning is emitted when an expression resolves to `ManiType::Unknown`.
`undefined_func() + 1` still compiles silently.

### 5b. `tif` Condition Type Is Not Enforced
✅ FIXED. `semantic/analyzer/expressions.rs:216` now explicitly checks
`tcond.ty != ManiType::Trit && tcond.ty != ManiType::Bool3` and returns a type error.

### 5c. `Tand`/`Tor`/`Txor` Return `ManiType::Trit` — Too Narrow
✅ FIXED. `semantic/analyzer/type_inference.rs:52-55`: when both operands are `Bool3`,
the result is `Bool3`. Otherwise falls back to `Trit`.

### 5d. `Tryte` Implementation Bug — DESIGN VIOLATION
⚠️ PARTIAL.
- IR type mapping: ✅ FIXED — `ir/types.rs:124` now `ManiType::Tryte => IRType::I16`
  (was I8; 6-trit max 364 requires I16).
- Range check: ❌ NOT YET — `type_inference.rs:458` still reads
  `ManiType::Tryte => Some((-13, 13))` which is the 3-trit range. Should be `(-364, 364)`.

This means the IR emits the right width but the semantic analyzer still rejects valid 6-trit
`tryte` literals (e.g., `let t: tryte = 200;` gets a spurious "out of range" error).

## 6. Optimizer Issues

### 6a. Constant Propagation Is Single-Pass, Intra-Block Only
❌ NOT YET. CP still collects constants from `Assign` in one forward pass per block.
True dataflow CP (worklist / SSA-based) not implemented.

### 6b. No Inlining Pass
❌ NOT YET. No function inlining pass exists. Small functions and lambda calls are still
emitted as full call sequences.

### 6c. No Loop-Invariant Code Motion (LICM)
❌ NOT YET. No LICM pass. Not blocking current work.

## 10. Design Cross-Reference — DESIGN.md vs Implementation

### 10a. `tryte` = 6 trits — DESIGN VIOLATION (partial fix)
⚠️ IR type fixed (I16). Range check in `type_inference.rs:458` still wrong: `(-13, 13)`.
**Must finish.** (See §5d.)

### 10b. `tresult` — Core Language Feature, Not a Stray Keyword
❌ NOT YET. `tresult` keyword is lexed but has zero parser coverage. DESIGN.md §6 specifies:

```manit
tresult read_sensor() {
    Ok(v)         => process(v),
    Unknown(hint) => log(hint),
    Err(e)        => panic(e),
}
```

Implementation needed:
- **Lexer:** `Tresult` token already exists ✅
- **AST:** Add `TresultExpr { subject, ok_pat, ok_expr, unknown_pat, unknown_expr, err_pat, err_expr, span }`
- **Parser:** `tresult <expr> { Ok(<pat>) => <expr>, Unknown(<pat>) => <expr>, Err(<pat>) => <expr> }`
- **Semantic:** Verify subject type is `Result<T, E>` (3-variant enum); bind pattern vars
- **IR:** Lower to `TritBranch` on the discriminant trit (+1 = Ok, 0 = Unknown, -1 = Err)

Also verify: `Result<T, E>` in stdlib has three variants (Ok, Unknown, Err), not just two.

### 10c. `tcon` and `tany` Operators
❌ NOT YET. Absent from lexer, parser, semantic, and both backends.

| Operator | Semantics |
|----------|-----------|
| `tcon` | Consensus: +1 if both +1, -1 if both -1, else 0 |
| `tany` | Any: +1 if either +1, -1 if either -1, else 0 |

Need full pipeline: lexer keyword → parser BinOp → semantic type check (Trit×Trit→Trit,
Bool3×Bool3→Bool3) → LLVM (cmp chains) → T3ISA (TCON, TANY opcodes).

### 10d. `int` = Arbitrary Precision — Design vs Implementation
❌ Decision pending. `ManiType::Trint => IRType::I64`. DESIGN.md §3 calls `int`
"arbitrary precision, unbounded." Current bound: ±9.2×10^18.

**Recommendation:** Rename `Trint` → `T54` in the type table and update DESIGN.md to
document `int` as an alias for `t54` (bounded at ±3.4×10^25 for 54 trits). Opens a future
tracking issue for true arbitrary precision via `num-bigint`.

### 10e. Concurrency — Not Yet Implemented (Phase 6)
❌ `spawn { }`, `channel<T>()`, `async fn / await`, `Mutex<T>` — all specified in
DESIGN.md §7, none implemented. Expected Phase 5–6 work. **Not blocking.**

### 10f. LOADT / STORET — T3ISA Single-Trit Memory Ops
❌ NOT YET. `isa.rs` and `emulator/execute.rs` have no LOADT/STORET opcodes.
DESIGN.md §10 specifies `LOADT Rd, [Rs+imm]` / `STORET Rs, [Rd+imm]` for single-trit
load/store. Needed when `trit`-typed struct fields are accessed individually.

### 10g. `t27` Range — Minor Error in DESIGN.md
✅ FIXED. DESIGN.md now correctly says `(3^27−1)/2 ≈ ±3.8×10^12`.
